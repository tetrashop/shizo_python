## معرفی پروژه
**ShizoImprove** یک ابزار متن‌باز و چندسکویی (Cross-platform) برای **بایگانی و نسخه‌بندی فایل‌ها بر اساس تاریخ آخرین تغییر** است.

هدف اصلی:  
مدیریت هوشمند فایل‌های پروژه‌های مختلف با دسته‌بندی خودکار در پوشه‌هایی به‌نام پروژه و تاریخ، به‌گونه‌ای که هر نسخه از فایل‌ها به‌راحتی قابل ردیابی باشد.

نسخهٔ اصلی (C# / .NET Framework) برای ویندوز طراحی شده بود. این نسخه بازنویسی‌شده به زبان **پایتون ۳** است و روی **ترمکس / لینوکس / ویندوز / مک** اجرا می‌شود.

### ساختار خروجی
```

~/ShizoImprove/
├── ProjectName/
│   ├── 2026-05-17/
│   │   └── relative/path/to/file.py
│   ├── 2026-05-18/
│   │   └── relative/path/to/file.py
│   ├── 2026-05-18.zip          (در صورت فعال بودن فشرده‌سازی)
│   └── ...
└── Improved/
└── ProjectName/
└── latest_versions/

```

## پیشینه و سیر تکامل
1. **کد اصلی** (C#):  
   یک کتابخانهٔ .NET که فایل‌ها را از یک مسیر ریشه اسکن می‌کرد و بر اساس نام پروژه (یا پسوند) در مسیر `C:\ShizoImprove\ProjectName\YYYY-MM-DD\...` کپی می‌کرد.  
   این کد چندین باگ جدی داشت (مهم‌ترین آن: شرط نبودن فایل مقصد به‌اشتباه روی مبدأ چک می‌شد و عملاً کپی بی‌اثر بود).

2. **بازنویسی پایتون اولیه**:  
   ترجمهٔ مستقیم منطق کد به پایتون همراه با رفع باگ‌های آشکار. در این مرحله باگ کپی همچنان وجود داشت و تست‌ها آن را آشکار کردند.

3. **فاز تست و رفع باگ‌های پیاپی**:  
   با نوشتن تست‌های واحد (Unit Tests) خطاهای زیر شناسایی و برطرف شدند:
   - مشکل `mtime` در فایل‌های موقت (`tmpfs` ترموکس)
   - بازنویسی نشدن فایل مقصد با نسخهٔ جدیدتر
   - اشتراک مسیر خروجی بین تست‌ها
   - ایجاد پوشه در حالت `dry-run`
   - اخطار `SyntaxWarning` در راهنمای آرگومان‌ها

4. **نسخهٔ Advanced کنونی**:  
   افزودن قابلیت‌های مدرن (موازی‌سازی، checksum، فشرده‌سازی، الگوهای glob/regex، exclude patterns، dry-run مستقل از فایل‌سیستم) و پوشش کامل تست.

## خطاهای اصلی و راه‌حل‌ها

### ۱. مشکل `copy_file_if_newer` و عدم بازنویسی فایل جدیدتر
**خطا:**  
در کد اصلی شرط `if (!File.Exists(AllFiles[i]))` به‌اشتباه مبدأ را چک می‌کرد نه مقصد را. در نسخهٔ پایتون اولیه نیز از `shutil.copy2` استفاده می‌شد که `mtime` مبدأ را به مقصد کپی می‌کرد و مقایسه‌های بعدی را بی‌اثر می‌ساخت.

**راه‌حل:**  
استفاده از `shutil.copy` (نه `copy2`) تا `mtime` مقصد برابر با زمان جاری شود، یا حذف فایل مقصد و سپس کپی مجدد. در نسخهٔ نهایی از متد `copy_file_if_newer` با منطق صحیح و امکان checksum استفاده می‌شود.

### ۲. عدم تغییر `mtime` در فایل‌های موقت (tmpfs)
**خطا:**  
در ترموکس، `os.utime` روی فایل‌های `tmpfs` تاریخ را به‌درستی تنظیم نمی‌کرد و تاریخ واقعی سیستم (امروز) خوانده می‌شد.

**راه‌حل:**  
در تست‌ها: تست مستقیم متد `copy_file_if_newer` با فایل‌های مقصد دست‌ساز و `mtime` تنظیم‌شدهٔ دقیق.  
در کد اصلی: اتکا به `os.stat().st_mtime` واقعی فایل‌ها (که در عمل معتبر است).

### ۳. ایجاد پوشه در حالت `dry-run`
**خطا:**  
متد `_archive` حتی در حالت `dry_run=True` نیز `_copy_one` را صدا می‌زد که منجر به ساخت پوشه‌های مقصد می‌شد.

**راه‌حل:**  
انتقال کامل منطق `dry-run` به همان سطح `_archive` و عدم فراخوانی `_copy_one`. فقط پیام چاپ می‌شود.

### ۴. اخطار `SyntaxWarning` در آرگومان `--exclude`
**خطا:**  
رشتهٔ `'\.git'` در `help` پارامتر `--exclude` به‌عنوان escape sequence نامعتبر هشدار می‌داد.

**راه‌حل:**  
استفاده از `r'\.git'` (raw string) در مستندات آرگومان.

### ۵. اشتراک مسیر خروجی بین تست‌ها
**خطا:**  
تست‌ها از `~/ShizoImprove` یکسان استفاده می‌کردند و روی خروجی یکدیگر تأثیر می‌گذاشتند.

**راه‌حل:**  
اختصاص یک پوشهٔ موقت جداگانه برای هر تست با `tempfile.mkdtemp` و پاکسازی آن در `tearDown`.

### ۶. مشکل `AssertionError` در تست `test_date_copy_overwrite`
**خطا:**  
تاریخ در مسیر خروجی به‌دلیل اختلاف UTC/Local زمان‌ها متفاوت بود.

**راه‌حل:**  
جایگزینی تست بازنویسی با تست مستقیم منطق `copy_file_if_newer` و استفاده از `time.mktime` برای زمان محلی.

## معماری کد

### کلاس `ShizoImprove`
| متد/ویژگی | شرح |
|------------|------|
| `__init__` | دریافت مسیر ریشه، نام پروژه، پوشهٔ خروجی و تنظیمات (exclude, dry_run, workers, compression, checksum) |
| `_scan` | پیمایش بازگشتی فایل‌سیستم با اعمال الگوهای حذف |
| `_archive` | هستهٔ اصلی بایگانی: فیلتر فایل‌ها بر اساس predicate و اجرای کپی (با پشتیبانی از موازی‌سازی) |
| `archive_by_project` | بایگانی فایل‌هایی که نام پروژه در مسیرشان باشد |
| `archive_by_extension` | بایگانی بر اساس پسوند (مثلاً `py`) |
| `archive_by_glob` | بایگانی بر اساس الگوی glob (مثلاً `*.py`) |
| `archive_by_regex` | بایگانی بر اساس عبارت منظم (مثلاً `^test_.*\.py$`) |
| `copy_file_if_newer` (static) | کپی هوشمند: فقط در صورت جدیدتر بودن مبدأ یا عدم وجود مقصد (با checksum اختیاری) |
| `_build_dest` | ساخت مسیر مقصد بر اساس تاریخ `mtime` فایل |
| `_compress_output` | فشرده‌سازی پوشه‌های تاریخ به فایل‌های zip |
| `clear_cache` | حذف تمام محتویات خروجی (به‌جز پوشه `Improved`) |
| `move_to_improved` | انتقال آخرین نسخهٔ فایل‌ها به پوشه `Improved` بدون تاریخ |
| `_file_checksum` (static) | محاسبهٔ SHA256 فایل برای مقایسه محتوا |
| `_is_improved_path` | تشخیص مسیرهای مربوط به پوشه `Improved` |

### جریان اجرا
1. `ShizoImprove` با مسیر ریشه و نام پروژه ساخته می‌شود.
2. متد `_scan` تمام فایل‌ها را (به‌جز موارد excluded) جمع‌آوری می‌کند.
3. یکی از متدهای `archive_by_*` فراخوانی می‌شود.
4. `_archive` فایل‌ها را فیلتر می‌کند.
5. برای هر فایل، `_copy_one` → `copy_file_if_newer` اجرا می‌شود.
6. در صورت فعال بودن `compression`، پوشه‌های تاریخ zip می‌شوند.
